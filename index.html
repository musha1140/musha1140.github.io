WHAT IF A SONG WAS THE PASSWORD?

A MIDI file never changes. Same notes, same hits, same timing, every single time you open it. That makes it a constant, and a constant can be a key. Every note pays three bytes into the keystream: the pitch, how hard it was hit, and when it lands.

Type something. Your letters turn into bits, the song turns into bits, and XOR stacks them into the cipher. Run XOR again with the same song and your message comes right back out, bit for bit. Nothing lost. Wrong song, you get garbage.

SO WHERE DO THE PRIMES COME IN?

The grid has to decide which cells light up, and I let the primes decide. π(x) counts how many primes sit at or below x. Every note adds the next cipher byte to a running total, π of that total picks a cell, and the cell flips. Hit an odd number of times, it stays lit. Hit an even number of times, it cancels to a red zero. Not empty. Cancelled.

Same message, same song, same board. Every time. Change one letter and the whole board moves.

HOW DID THAT TURN INTO A PRIME FINDER?

GS grew a parallel Erdős–Woods search, and it matched OEIS A059756, the known list, number for number. That search became the convergence gate in MDTGF. The gate feeds a deterministic pipeline, and the pipeline found a real 2048-bit probable prime. OpenSSL checked it on its own and agreed. So yes, it finds primes, and that is proven.

SO WHAT DID I PROVE?

That a song can be a key, lossless, bit for bit. That the same grid, steered by π, grew into a search that found a real 2048-bit prime, and that OpenSSL agrees. Two years, one idea, every piece of it built and checked.
