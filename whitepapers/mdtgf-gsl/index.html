MDTGF & the GSL Machine

MDTGF, the lattice, the operating system, and the node in assembly

Two planes, kept evidentially separate on purpose: a multi-dimensional lattice experiment that measured its own central claim and published the null result, and a from-scratch 32-bit x86 operating system whose every byte is emitted without a compiler. This paper describes both planes, the integrity machinery they share, and the phase now in assembly: the machine leaving the emulator for an always-on node.

Plane one, the lattice

A seeded, deterministic field sweeps two periodic streams across a multi-dimensional co-occurrence lattice; cells where both streams clear a threshold become convergence gates, and only gate coordinates are allowed to spend expensive work, a hash block and primality rounds. The colour law is the classification: one stream's axis paints one primary, the other's the second, convergence the third.

The experiment's honest headline is its own refutation: measured against uniform random selection, the gate's prime yield is statistically indistinguishable (z = 0.85), for a reason the write-up states plainly, the hash decorrelates coordinate structure from digest structure. The gate was re-framed as what the measurement supports: a deterministic scheduler that concentrates work, not an oracle that predicts primes. A second selector's apparent signal failed replication and was retired unpublished. The ledger of found primes stores recipes, not trophies, each entry re-derived and re-verified on every test run.

The gate's search DNA predates the lattice: a parallel worker in the flagship MIDI repo hunts Erdős–Woods numbers, interval lengths k where every interior point of some [a, a + k] shares a prime factor with an endpoint, sanity-checked against the head of OEIS A059756. The sequence opens 16, 22, and those two numbers are folded into the constellation's own naming: one·six·two·two. The habit that matters carried forward intact, search deterministically, and keep an oracle in the loop that can call the search wrong.

Plane two, the machine

GSL is a 32-bit x86 operating system built with zero external toolchain: a hand-written instruction encoder in JavaScript emits every byte of the boot sector and kernel, from the real-mode entry through the protected-mode jump. The boot chain is the classical liturgy performed from scratch, segments and stack, teletype greeting, sector-by-sector kernel load, a graphics mode chosen so that the palette index is the cell classification, the address-line gate, a flat descriptor table, and the far jump into 32-bit code.

Above that sits a small desktop, window manager, taskbar, native apps, whose field viewer harvests its telemetry by reading pixels back out of the real framebuffer, so an occluding window genuinely hides cells. There is no networking and no filesystem by design; documentation is baked into the image.

Integrity as a habit

The same hash function exists in four roles across the project, and the most important copy is hand-encoded in the kernel and verified on the metal against the standard test vector at every boot. Modules are refused on digest mismatch, one corrupted byte on disk halts the machine before the desktop. An append-only audit log is hash-chained entry to entry and cross-checked by an independent implementation outside the machine. The test discipline is explicit: a feature is done when a committed test exercises both its success and its documented failure paths, a definition the repository applies to itself in public, run-ledger and all.

The edge today

The public story and the working machine are deliberately different deployments. A showcase rides the edge as static content; the application lives on an edge-pages project; and the machine itself sits behind a worker whose gate is enforced in code, the pragmatic stand-in, on a domain the edge provider owns, for the Zero Trust Access policy the repository documents for a domain of one's own.

The phase in assembly, GSL on the Pi

The next phase is being assembled through this consolidation, not after it: GSL leaves the emulator for an always-on node, a Debian-based distribution targeting a Raspberry Pi 4B+, semi-built on Cloudflare as this is written. The deployed half already exists: the worker gate, the pages app, the documented Access path with a one-time-PIN policy. The remaining half, the Pi image itself, is assembled while the major projects are pulled together, so the node arrives already knowing what it hosts.

Behind its private tunnel, with no inbound ports, the node carries the constellation's serious side: the working lattice and its prime ledger, the MIDI family's derive-and-verify endpoints, the integrity verifiers, and, in the last phase, the deferred engines that are only allowed to become services there (see the flow-and-proof paper). The public faces stay on the edge; the machine stays home.

Deliberate omissions, this paper describes structure and mechanism, not implementation absolutes. Exact constants, derivation orders, offsets, thresholds, schedules and parameter choices are omitted by design: enough to see the shape and the work, never enough to reconstruct the keys. The repositories and live artifacts remain the reference implementations.

status

Plane one is complete and its measurements published, null result included; the machine boots, verifies itself, and passes its test suite across repeated boots. The Pi node is the phase in assembly.
