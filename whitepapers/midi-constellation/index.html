The Song is the Key

The MIDI Project, GS · kilo · key-midi · slayy · the archives

A family of symmetric ciphers whose key material is a musical performance. The same file that plays the room derives the keystream that conceals the message, and the encryption is painted, event by event, in playback time. This paper describes the architecture that survived five generations of the idea and the verification habits that grew around it.

Premise

Every generation of the project holds one premise fixed: the key is not a password remembered by a person but a performance carried by a file. Whoever holds the same song can derive the same keystream; whoever does not, cannot. Key distribution becomes something people already do, sharing music.

The core transform is an involution: applying it twice with the same song returns the original bytes exactly, losslessly. Encrypt and decrypt are the same gesture, which keeps every generation of the tooling honest, the decoder is not a second program that might drift, it is the encoder pointed backwards.

Keystream derivation

Two derivation philosophies coexist in the family. The parsed-performance line reads the song as music: each performance event contributes a fixed-width slice of key material in playback order, so the keystream inherits the song's structure, its rhythm literally becomes the cipher's cadence. The whole-file line reads the song as bytes: the entire container is digested through a cryptographic hash into a fixed-size key for an authenticated envelope, trading musical structure for uniformity.

A third, playful variant offsets the keystream by a property of the person typing, a cadence measured at the keyboard, so the same song and the same message still produce a different weave per sender. Which properties, which widths, and in which order events pay in, are among the absolutes this paper omits.

The envelope and its checks

The XOR weave is wrapped in an authenticated symmetric envelope in the modern generations, a standard AEAD construction with a stretched passphrase in the flagship, and a hash-derived key in the rewrite. Integrity is checked at more than one altitude: per-character checks inside the payload, an authenticated tag around it, and, most characteristically, a decompiler that re-derives the keystream from the song and confirms the round trip.

The family states its own security posture plainly; the flagship's README says 'this is art, not security', and means it. The work is a study in key-material provenance and verification habits, not a product cipher, and the papers keep that sentence attached to it.

Visualization as verification

Nothing in the family renders a decoration. The 64-cell gate grid, the earlier 4×4 boards, and the rewrite's QR matrix are all pictures of the actual state: cells fire as the transform touches them, in transport time, synchronized to playback. The rewrite pushes this to its logical end, the ciphertext is painted as scannable code while the song plays, with register deciding the colour law (treble one way, bass the other), so a correct picture is itself a check that the machine did what it claims.

The lineage of the grid is a lineage of the idea: 4×4 origin boards in the archives, the 64-cell flagship, then a matrix whose module count is chosen by the payload. Each generation kept the involution and moved the visual law forward.

The image arm

The constellation's image arm hides payloads in pictures rather than songs: the message rides the least-significant bit of a single colour channel, one bit per pixel, terminated by a sentinel the extractor searches for. It is deliberately the simplest member of the family, lossless containers only, no robustness against re-encoding, and exists to complete the set: text in songs, text in text (see the zero-width paper), and text in images, all under one involution habit.

Deliberate omissions, this paper describes structure and mechanism, not implementation absolutes. Exact constants, derivation orders, offsets, thresholds, schedules and parameter choices are omitted by design: enough to see the shape and the work, never enough to reconstruct the keys. The repositories and live artifacts remain the reference implementations.
