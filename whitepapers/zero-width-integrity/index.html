Zero-Width Integrity

Watermarker · steganographr lineage, text hidden in text

Invisible Unicode as a carrier: messages and watermarks interleaved into ordinary text using characters that render as nothing, survive copy-paste, and can be found and verified later. This paper describes the carrier, the difference between hiding and watermarking, and the verification pass that turns an invisible mark into a tamper check.

The carrier

A small alphabet of zero-width Unicode characters encodes binary into text that renders identically with and without its payload. The carrier travels wherever the text travels, chats, documents, clipboards, because it is the text. Which characters map to which symbols, and how the payload is framed and terminated, are absolutes this paper omits.

Hiding versus watermarking

The steganographic use conceals a message for a recipient who knows to look. The watermarking use inverts the audience: the author embeds a mark in their own writing so that they can later prove a copy is theirs, and, just as importantly, prove whether a copy has been altered. Same carrier, opposite trust direction.

The live tool implements the second use end to end: write, watermark invisibly, publish; later, paste any copy back in and the verifier reports whether the mark survived intact, was stripped, or was disturbed, the disturbance itself being the tamper evidence.

The encrypted lineage

An earlier line of the work pairs the carrier with an authenticated symmetric layer and a stretched key, so that a discovered payload is still an opaque one. That line remains a prototype; the shipped tool keeps the carrier honest and the cryptography out of the promise.

Stated limits

The carrier is not robust watermarking: aggressive normalization, re-typing, or format conversion that strips invisible characters removes the mark, and the verifier says so rather than pretending otherwise. The claim is integrity signalling on faithful copies, not survivability against a determined launderer.

Deliberate omissions, this paper describes structure and mechanism, not implementation absolutes. Exact constants, derivation orders, offsets, thresholds, schedules and parameter choices are omitted by design: enough to see the shape and the work, never enough to reconstruct the keys. The repositories and live artifacts remain the reference implementations.
